# 권한 기능 적용 전 준비

이번 버전은 기기별 Firebase 익명 인증 UID와 세션 참여 권한을 사용합니다. 개설자(owner)는 권한을 관리하고 현장을 종료·재개할 수 있습니다. 입력자(editor)는 진행 중인 현장을 수정하고, 열람자(viewer)는 조회합니다. 새 참여자는 열람자로 시작합니다.

익명 인증은 해당 브라우저의 기기를 구분하며 실제 사람의 신원을 확인하지 않습니다. 기록자 이름은 직접 입력한 정보입니다. 코드를 아는 기기는 열린 현장에 열람자로 참여할 수 있으므로 코드는 필요한 참여자에게만 공유합니다. 브라우저 데이터를 지우거나 다른 PC·브라우저를 쓰면 다른 UID가 되며, 소유자 UID는 자동으로 이전되지 않습니다.

여러 PC에서 같은 개설자 권한을 사용하려면 새 현장을 만들기 전에 첫 화면에서 Google 계정으로 로그인합니다. 익명 기기로 만든 현장은 그 기기에 소유권이 남습니다. 기존 현장의 최초 작성자는 인증 기록이 없어 식별할 수 없으므로, 2026-10-19 이전 작업에서는 확인된 Firebase 프로젝트 관리 계정 `119gpt1@gmail.com`을 관리자로 지정했습니다. 이 계정으로 Google 로그인하면 기존 현장을 관리할 수 있습니다. 다른 참여자는 관리자가 편집 권한을 부여합니다.

## 배포 전 필수 작업

1. Firebase Authentication에서 익명 및 Google 로그인을 활성화합니다. `firebase deploy --only auth`로 firebase.json의 설정을 반영할 수 있습니다.
2. 기존 세션은 관리자 권한으로 백업합니다. 기존 세션에는 ownerId·closed·members가 없으므로 새 규칙으로 바로 교체하면 접근이 차단됩니다.
3. 유지할 각 sessions/{code} 문서에 `ownerId: 개설자의 인증 UID`, `closed: false`를 추가하고, sessions/{code}/members/{UID}에 `role: owner`, `name`, `joinedAt`을 만듭니다. 참여할 기존 기기는 members에 editor 또는 viewer로 등록합니다. 소유자 UID는 Firebase Authentication 사용자 목록에서 실제 개설자의 기기와 대조해야 합니다. 브라우저 데이터 삭제 시 관리자가 소유자를 복구해야 합니다.
4. 세션의 필수 키 `createdAt`, `updatedAt`, `buildings`, `states`, `personnelStats`를 확인합니다. 건물·상태·인원 배열의 길이가 일치해야 합니다. 미완성 세션은 관리자 검토 후 처리합니다.
5. 예전 최상위 briefings/{id} 데이터가 필요하면 해당 sessions/{code}/briefings 아래로 관리자 권한으로 이전합니다. 새 규칙은 최상위 briefings를 차단합니다.
6. 기존 Flutter 클라이언트는 새 인증·권한 규칙과 호환되지 않습니다. 운영 중인 구버전 클라이언트 사용을 정리하고 웹앱 새로고침을 안내합니다. 새 앱·새 규칙은 함께 적용해야 합니다. 이전 클라이언트를 계속 지원해야 한다면 별도 프로젝트·데이터베이스를 준비해야 합니다.
7. 에뮬레이터에서 개설·참여·권한 승격·동시 편집·종료·재개를 확인하고 배포합니다. 이 문서의 작업을 완료한 경우에만 배포 스크립트의 준비 변수를 지정합니다.

기존 세션의 개설자를 임의로 첫 방문자에게 배정하는 자동 이전은 제공하지 않습니다. 기존 현장은 인증된 프로젝트 관리자의 Google 계정에 연결하며, 새 방문자가 관리 권한을 가져갈 수 없습니다. 2026-10-19에 기존 현장 233개를 백업한 뒤 ownerId·closed와 관리자 members 문서만 추가했습니다. 기존 건물·호실·보고서·타이머 등 업무 내용은 변경하지 않았습니다. 건물 미설정 현장 39개도 삭제하지 않고 보존했습니다.

## 로컬 검증

Java 21, Firebase CLI가 있는 환경에서:

```powershell
npm ci
npm test
firebase emulators:exec --only firestore --project demo-safecheckboard "npm run test:rules"
npm run build
```

Chrome을 설치한 PC에서는 Authentication·Firestore 에뮬레이터를 함께 실행하여 브라우저 검증도 할 수 있습니다.

```powershell
firebase emulators:exec --only auth,firestore --project demo-safecheckboard "npm run test:rules && npm run test:e2e"
```

앱을 에뮬레이터에 연결하려면 `.env.development.local`에 `VITE_USE_EMULATOR=1`을 넣고 `npm run emulators`, 다른 창에서 `npm run dev`를 실행합니다. 에뮬레이터는 demo-safecheckboard 프로젝트의 Authentication·Firestore만 사용하며 운영 데이터에 연결하지 않습니다. 프로덕션 빌드는 에뮬레이터 플래그를 무시합니다.

검증 시 실제 운영 Firebase 프로젝트에 쓰기를 하지 마세요. 이번 환경에서는 설치된 Java 17에 맞춰 Firebase CLI 13.35.1의 에뮬레이터를 사용했습니다.

## 저장·경보의 동작

- 현황판은 서버가 확정한 변경을 표시합니다. 상태 변경과 감사 기록은 하나의 트랜잭션으로 저장합니다.
- 보고서·환자 목록은 변경 전 값, 내 입력, 서버 최신 값을 비교해 독립적인 변경을 병합합니다. 행 ID로 동시 추가·삭제를 구분합니다. 동일 항목의 충돌은 거절하며, 실패한 입력은 재시도할 수 있도록 현재 탭의 메모리에 남습니다.
- 실패한 변경과 입력 대기는 상단 저장 상태에 표시됩니다. 미저장 상태에서는 나가기를 막고 브라우저 종료·새로고침 시 경고합니다. 강제 종료·기기 전원 차단까지 입력 보존을 보장하지 않으며 민감한 환자 정보를 로컬 저장소에 별도로 복제하지 않습니다.
- 활동 중지 중에도 진입대 체류 시간과 위험 판정은 계속됩니다. 진입 중인 대는 삭제할 수 없습니다. 각 기기에서 경고음 켜기·테스트 버튼을 눌러 오디오를 활성화해야 합니다.
- 시간은 기기의 시각을 기준으로 합니다. 기기 시각 자동 설정이 필요하며, 브라우저가 백그라운드에서 실행을 중지하거나 소리를 차단하면 정시 경보를 보장할 수 없습니다. 복귀 시 경과 시간을 다시 계산합니다.

Firebase 동작 근거: [익명 인증](https://firebase.google.com/docs/auth/web/anonymous-auth), [트랜잭션](https://firebase.google.com/docs/firestore/manage-data/transactions), [보안 규칙의 인증·권한 조건](https://firebase.google.com/docs/firestore/security/rules-conditions).
